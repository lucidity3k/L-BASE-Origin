# L-BASE原典

## AIを信じる前に、判断の材料を確かめられるようにする

今のAIに必要なのは、答えを出す能力に加えて、その答えが何を受け取り、何を変え、何を根拠にしているのかを、人が確かめられる基盤です。

L-BASEは、発信者やAIの名前、文体、印象を信頼の代わりにするのではなく、原文・変換・評価のつながりを確認できる状態を目指す設計提案です。正しい答えを保証する仕組みではありません。人が判断するための材料を、失われたり混同されたりしにくい形で渡すことを目的とします。

本書はその目的と原則をまとめた公開用説明稿です。特定の製品の不具合率や、この構想の効果を実測した報告ではありません。

## 1. 出力の正誤だけでは、変化の過程は分からない

文章の一部が正しくても、入力と比べて次のような点が変わっているかもしれません。

- 誰が述べたことなのか。
- 何を対象にし、どこまでについて述べているのか。
- 何が論点になっているのか。
- 確認済みのことが留保されていないか。未確認のことが断言されていないか。
- 因果や責任の帰属が、根拠なく付け加えられていないか。

これらは、完成した出力だけを見ても比較できません。元の入力、出力、必要な文脈を対応させる必要があります。

元の記録が保存されていても、それがどの主張・変換・評価につながるのか分からなければ、判断の根拠として使いにくくなります。保存だけでなく、関係を保つことも重要です。

## 2. L-BASEの役割は、判断を代行することではない

L-BASEが目指すのは、判断材料の整理と提示です。何を根拠に、どの範囲について、どこまで確認したのかを区別します。

裁定、許認可、強制や、異議申立てを裁く役割を担うものではありません。案件の重大性等級や、人が何を受け入れるべきかを、一律に決めるものでもありません。

「L-BASEがそう判定したから正しい」という循環を作らず、説明から根拠へ戻って確かめられることを重視します。この基準は、L-BASE自身が作る説明や評価にも適用します。

## 3. 変化は、具体的な箇所と対応させて示す

以下は説明のために作った架空例です。実際の利用者の発言、製品の出力、実験結果ではありません。

**入力例**

> 対象は試験用の記録3件です。そこでは手順Aの完了を確認しました。実運用での効果は調べていません。

**出力例**

> この仕組みは、実運用で効果があることが確認されています。

この対比では、少なくとも次の変更を示せます。

- 対象が「試験用の記録3件」から「実運用」へ広がっている。
- 確認した内容が「手順の完了」から「効果」へ置き換わっている。
- 「調べていない」が「確認されている」という断言へ変わっている。

提示された入力には、その断言を支える記述がありません。ただし、この比較だけで、現実に効果がない、故意に誤解させた、誰かに損害を与えた、とまでは判断できません。

必要なのは、確認できた変化を明確に示すことと、その先の結論には別の根拠が必要だと区別することです。

## 4. 設計上の六つの原則

1. **原本を加工文で上書きしない。** 原文、転記、翻訳、要約、評価を区別して保持します。
2. **加工物から、その入力と原本へたどれるようにする。** 途中の記録が不足している場合は、その欠落を明示します。
3. **AI評価の条件と結果を残す。** 実際に得られたモデル・版、入力、生出力、確度を記録し、未提示の値は不明として扱います。
4. **根拠不足を推測で埋めない。** 裏付けられない個別の判断は、判断を進められない状態（blocked）として区別します。
5. **人の判断をAIが代理決定しない。** 未決定の事項を、既定値や推奨という形で確定済みにしません。
6. **同じ入力と規則版による機械判定を再現可能にする。** 規則と対象を固定した照合結果を確かめられるようにします。

これらは満たすべき設計条件です。本書が存在するだけで、実際の仕組みが全条件を満たしたことにはなりません。

## 5. AIによる検討と、機械による照合を分ける

AIは、主体、範囲、論点、確度、因果、責任帰属などの意味の変化を検討するために用います。所見には、対象箇所と確認範囲を結び付けます。AIの所見自体も、検討対象です。

機械による照合は、保存したデータの一致、引用箇所、位置、参照関係など、あらかじめ定義した規則で確かめられることを扱います。

両者の結果は独立して保持します。平均したり、片方で上書きしたり、一つの総合合否へまとめたりしません。

引用が一致していても、その引用が所見を裏付けるとは限りません。ハッシュが一致していても、内容の真実性、発言者本人性、意味の同一性が証明されたわけではありません。AIの確度も、校正済みの正解確率だとは限りません。

同じ入力・規則版による機械照合の再現性と、AIを再実行して同じ文章や候補が出ることは、別の問題です。

## 6. 不明、失敗、訂正を消さない

「未取得」「照合していない」「照合が一致しない」「意味を評価していない」「確認した範囲で裏付けがない」は、同じ状態ではありません。

所見が0件だったことも、問題が存在しないという証明にはしません。ある部分の不足を、資料全体の無価値や、別の部分の不合格へ無条件に広げないことも必要です。

根拠に基づく訂正であっても、元の入力、訂正箇所、訂正根拠を残します。過去の記録を、後から生成した出力で消しません。

出力を作り直させる再生成は基本動作にしません。必要なのはまず、取得した出力にどのような根拠があり、何が未確認なのかを示すことです。この方針だけで、すべての処理の再試行を禁止したり、例外や費用負担を決めたりはしません。

評価の未完了や失敗だけを理由に、取得済みの出力を人から隠したり、提示を遅らせたりする設計にはしません。独立した開示制限がある場合は、その主体・根拠・適用を評価結果と区別します。

## 7. 確認できた変更と、責任の判断を分ける

主体や発言の範囲、論点などの変更が根拠付きで確認できた場合、故意や実害が未証明というだけで、その変更を軽く扱うべきではありません。一方、変更が確認できたことだけで、故意、不当性、実害や責任まで断定もしません。

根拠のない断言は、対象の主張と確認した範囲を示して「要注意」と記録します。未確認と、確認した範囲で裏付けを得られなかったことを区別し、「要注意」を直ちに「虚偽」と同一視しません。

最終判断は基本的に人が行います。ただし、人が最終判断することを理由に、提供元企業の責任まで利用者個人へ一律に移すことはしません。

どの人・企業が、どの行為について責任を負うのかは、具体的な関係と根拠を要する別の判断です。L-BASEは、その判断に必要な材料を渡す立場であり、企業や個人への責任認定を自動化する立場ではありません。

## 8. 原本の保持と、原本の公開は別である

原文全体を保持することと、分析する部分を選ぶことを分けます。対象箇所、必要な文脈、誰が何のために範囲を選んだかを残します。

同時に、原本を保持していることは、誰にでも公開・再配布してよいことを意味しません。個人情報、秘密情報、第三者の権利を守る必要があります。

公開用の説明や伏字版は、原本と区別します。非公開部分を公開読者が確認できるとは主張しません。読者が検証できる範囲と、アクセスできないため確認できない範囲を明示することも、検証可能性の一部です。

## 9. 何が提案で、何が未確認か

本書は、L-BASEの目的と設計原則を説明する文書です。具体的なモデル、実装方式、運用上の権限配置、料金や評価尺度を確定するものではありません。

この構想が社会的信用や理解を高めるか、費用に見合うか、安定して運用できるかは、対象と条件を定めて別途検証する必要があります。公平に扱う方針と、公平性が実証された結果は区別します。

L-BASEを使うかどうかも、提示された材料から何を受け入れるかも、利用する人が判断します。

本書は原典を編集した説明文であり、原資料全文の公開ではありません。編集にはAIによる支援を用いています。厳密なモデル識別子・版は確認できておらず、数値的な確度は未測定です。架空例は考え方の説明であり、実測された検出性能ではありません。

## 結び

AIを社会の基盤として使っていくなら、答えの生成能力とともに、その答えを人が確かめるための基盤が必要です。

L-BASEが目指すのは、「このAIやL-BASEを信じてください」ではなく、**「何を根拠にそう言うのかを、人が確かめられる状態にする」**ことです。
